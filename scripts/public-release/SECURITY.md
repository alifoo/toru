# Security

Do not report credentials, private recordings or exploitable vulnerabilities in public issues.

Use GitHub's private vulnerability reporting in the repository's Security tab. Before publishing this repository, the maintainer must enable that channel and verify that a private report can be submitted. It is not available from a standalone offline archive. No security email address is asserted here.

For local testing, use demo accounts and bind access to trusted clients. Public hosting requires verified browser isolation, HTTPS, correct origin/egress controls, secret storage and account separation. Do not disable the browser sandbox merely to make deployment succeed. Redaction checks do not guarantee that every visible piece of personal information is hidden.

The initial release is a beta with no support SLA. Report the exact release/commit, operating system, browser/driver versions and safe reproduction steps. Do not include session cookies, API keys, full page contents or customer data unless arranged through a private authorized channel.
